## Select the source objects

The connection's `id` is the flow's `source`. Each entry under `tables` names a
destination table and links its source `object` to a contract. The contract lists
the columns and keys you expect. Replace the synthetic object and contract with
yours before deploying.

## Reading behaviour

The copy extracts the selected date window, or the selected dataset when no date filter is required. Choose the downstream store behaviour
for repeated snapshots; this connector does not maintain an incremental watermark.

This source requires an Azure integration runtime. Set `runtime_kind`
to match the deployed runtime, and use its name in `integration_runtime`.

Microsoft 365 uses JSON landing with the configured application credentials.
Grant that application access to the landing storage and complete Microsoft Graph
Data Connect consent and dataset permissions. Always set
`source_options.requires_date_filter` to `true` or `false` according to the
dataset requirements. When it is `true`, `source_options.date_filter_column` is
also required. Extraction uses
the trigger window. Source column names must match contract names.

## Keep the destination current

The copy selects data again for each run. The default downstream store appends
rows, so repeated snapshots can produce repeated rows. Choose
[upsert or history](/docs/how-to/keep-a-table-current) with a reliable ordering
column when you need current rows or versions. A row absent from a later
snapshot is not a deletion instruction.
