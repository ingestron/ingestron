## Select the source objects

The connection's `id` is the flow's `source`. Each entry under `tables` names a
destination table and links its source `object` to a contract. The contract lists
the columns and keys you expect. Replace the synthetic object and contract with
yours before deploying.

## File selection and format

Use `mode: all`; this native reader has no modified-time window filter.

The object is the relative URL to one response. `files` names its landing file;
wildcards are rejected. Set `format` to the response format the downstream reader
will read.

HTTP uses GET by default. Set `source_options.request_method` to `POST` and
`request_body` when the download endpoint requires a request body, as the
sample flow shows. Credentials remain in the connection's secret references.

Set `format` to the format Databricks will read; ADF copies the files as they are.
`options` configures the downstream reader, for example CSV headers. Contract
column types are passed as schema hints when `schema_hints` is enabled.

## Files changed more than once

A file copied again can replace the landed file, while Auto Loader reads each
file once by default. Prefer sources that write new files rather than rewriting
old ones. Choose [store behaviour](/docs/how-to/keep-a-table-current) for the data
inside those files separately from which files ADF copies.
